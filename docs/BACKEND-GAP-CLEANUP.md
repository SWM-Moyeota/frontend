# 백엔드 미지원 기능 정리 이력

프론트엔드에 화면·코드는 있었지만 백엔드(Backend 저장소 `develop`)에 대응 API 가 없어 **동작하지 않거나 가짜 값을 보여주던 기능**을 걷어낸 기록이다.
원칙: 실데이터로 바꿀 수 있으면 바꾸고, 없으면 요소·라우트·코드를 제거한다. "준비 중" 같은 자리표시 문구로 대체하지 않는다.

- 프론트 기준: `refactor/remove-unused-screens` (origin/develop `79ad602` 위)
- 백엔드 기준: Backend `develop` `1a75f82`
- 상세 근거(파일:라인)와 백엔드 엔드포인트 전체 목록: `_workspace/102_audit_frontend_backend_gap.md`

## 2. 추가·변경한 것

- 12 매너 서약 맨 아래에 위치 공유 동의 항목 추가: 「운행 중 내 위치를 동승자와 공유하는 데 동의해요 — 매칭된 운행 동안에만 위치를 쓰고, 운행이 끝나면 공유도 함께 끝나요」. **서버에 저장 필드가 없어 전송하지 않는다**(가입 버튼 활성 조건에만 사용).
- 하단 탭·마이페이지 제목 「마이」 → 「마이페이지」, 탐색 제목 「동승 — 내 주변」 → 「근처 동승 찾기」, 홈 인사말 → 「{이름}님, 반가워요」.
- 33 도착 완료가 운행 종료 직후 방 정보를 잃던 버그 수정(`finishedRide` 로 보존).
- 10 프로필 만들기(·09)에 **만 14세 미만 가입 차단** 추가(`AuthPolicy.MIN_AGE`·`isOldEnough`, 만 나이·생일 당일 통과). 개인정보 보호법상 법정대리인 동의 없이는 가입시킬 수 없어 동의 절차 대신 가입을 막았고, 개인정보 처리방침의 「만 14세 미만은 가입할 수 없습니다」 고지와 동작을 맞춘 것이다. **서버에는 연령 제한이 없다**(`UserRegisterRequest` 는 `birthDate` 에 `@Past` 뿐) — 즉 앱만의 방어선이라 **API 를 직접 호출하면 우회된다.** 서버에도 같은 검증이 필요하다(§4 와 성격이 반대인 공백: 여기선 백엔드가 **더 막아야** 한다).

### 회원 탈퇴 (2026-10-13)

- **계약**: `DELETE /api/v1/users/me`, 본문 `{"password":"..."}` → **204**. Bearer 필수.
  Retrofit 의 `@DELETE` 는 본문을 못 실어 `@HTTP(method="DELETE", hasBody=true)` 를 쓴다
  (`UserApi.deleteAccount` KDoc). 인증이 필요하므로 `AuthApi` 가 아니라 **`UserApi`** 다.
- **문구는 서버 동작만 적는다** (`AccountDeletionWarnings`): 다시 로그인 불가 · 채팅방 전부 나감
  (상대에게는 「탈퇴한 사용자」) · 자주 가는 곳 삭제 · 같은 번호 30일 재가입 불가.
  **지난 합승 기록은 서버가 지우지 않는다** — "모든 기록이 사라져요" 같은 말을 쓰지 않는다.
  이 네 줄은 `AccountDeleteRulesTest` 가 못 박는다.
- **진행 중인 합승이 있으면 탈퇴할 수 없다**(409 `USER110`). 앱은 미리 막지 않는다 — "지금 내가
  타고 있는 방"을 묻는 엔드포인트가 없어(§4 와 같은 공백) 서버에 물어봐야 안다.
- ~~**남은 Play 요건**: 스토어 등록용 웹 탈퇴 안내 페이지.~~ **2026-10-14 해소.**
  `legal.moyeota.p-e.kr` 에 약관·개인정보 처리방침·계정 삭제 안내를 올렸고 `SupportLinks` 의 네 값이
  채워졌다. 35 에 「안내」 카드(개인정보 처리방침·이용약관·문의하기)가 생기고, 계정 삭제 안내는
  **37 안에서** 「지워지는 것과 남는 것 자세히 보기」로 연다(35 에 중복 입구를 두지 않았다).
  주소를 null 로 비우면 그 행이 사라지는 동작은 그대로다 — 페이지가 내려갔을 때의 긴급 복구 경로다.

### 지난 탑승 기록 (2026-11-01)

- **계약**: `GET /api/v1/users/me/parties` → **200**. Bearer 필수(무토큰 → 401 `USER005`).
  쿼리는 **`cursor`(Long, optional) · `size`(Int, 1~50, 기본 20) 둘뿐**이다.
  응답은 `{"rides":[...],"nextCursor":Long?,"hasNext":Boolean}` 이고 `rides[]` 한 건은
  `partyId`·`departure`·`destination`·`pickupTime`·`dropoffTime`·`totalFare`·`farePerPerson`·
  `currentMembers`·`members[]`(`publicId`·`nickname`·`imageUrl` 셋뿐)다.
  정렬은 `dropoffTime desc, matchId desc`. 실측(2026-11-01, 로컬 `:8080`)으로 전부 확인했다.
- ★ **「지금 내가 타고 있는 방」이 아니다.** 경로가 `parties` 라 「내 방 목록」처럼 읽히지만 서버는
  **하차 시각이 찍힌 기록만** 거른다(`dropoffTime is not null`). 실측: 내가 유일 멤버인
  `status=MATCHING` 방을 하나 들고 불러도 `{"rides":[],"nextCursor":null,"hasNext":false}` 였다.
  그래서 `ActivePartyRepository` 의 로컬 기억(방 id 를 DataStore 에 기억했다가 상세로 되살리는 것)은
  **한 줄도 건드리지 않았다** — 이것으로 걷어내면 진행 중인 방을 전부 잃는다(홈·탐색 배너가 사라지고
  매칭 화면 복귀가 끊긴다).
- ★ **`?status=FINISHED` 는 없는 파라미터다.** §4 가 적어 둔 그 경로는 구현되지 않은 추측이었고,
  붙여도 400 이 아니라 **200 + 조용히 무시**라서(실측: `?status=ACTIVE` → 200, 결과 동일)
  「동작한다」고 착각하고 지나간다. 필터는 필요 없다.
- **요금이 null 인 기록은 결함이 아니다.** `totalFare`·`farePerPerson`·`pickupTime` 이 셋 다 null 인
  것은 **1차 모드**(기사 없이 방장이 합승 종료)로 끝난 방이다. 화면은 그때 **요금 줄을 아예 그리지
  않는다** — 0원으로 보여 주면 「공짜로 탔다」는 거짓말이 된다. `RideHistoryRulesTest` 가 못 박는다.
- **1인 부담은 서버 값을 그대로 쓴다.** 서버는 `totalFare / currentMembers` **내림**인데 앱의
  `farePerPersonWon`(14·15 의 예상 요금)은 10원 단위로 올림/반올림한다 — 끌어다 쓰면 기록 화면
  금액이 실제 결제액과 어긋난다.
- **그리지 않는 것**: 상태 칩(서버가 상태를 안 준다) · 방장 표시(`host` 필드 없음) ·
  평점·매너 점수(평가 API 없음) · 「예정」 탭(예약 개념 없음) · 「2/3명」(정원을 안 준다).
- **탈퇴 409 를 이것으로 미리 막으면 안 된다.** 409 `USER110` 의 판정식은
  `existsOngoingByMemberId`(ACTIVE·COMPLETED·MATCHING·DRIVER_ASSIGNED·IN_RIDE)인데 이 응답은
  그중 아무것도 주지 않는다. 「막을 방이 없다」고 잘못 판정해 그대로 409 를 맞고, 사용자는 앱이
  확인했다고 믿는다 — §6 위쪽의 「앱은 미리 막지 않는다」는 **여전히 유효하다.**
  (실측 덧붙임: **비밀번호 검사가 먼저**다. 틀린 비밀번호 → 400 `USER111`, 409 는 그 뒤에만 나온다.)
- **남은 공백**: 「지금 내가 타고 있는 방」을 묻는 `GET /api/v1/matching/rooms/me` 는 아직 없다.
  그게 생기면 `RemoteActivePartyRepository.resolve()` 의 1단계를 서버 조회로 바꾸고 로컬 기억을
  캐시로 내릴 수 있다(지금의 `Verdict.Unknown` 경로가 그대로 캐시 폴백 자리다). **백엔드 요청 항목.**

### 메시지 신고 (2026-11-01)

- **계약**: `POST /api/v1/chat-rooms/{chatRoomId}/reports`, 본문
  `{"chatMessageId":Long(>=1),"reason":enum,"description":String?(<=500)}` → **201, 본문 없음**.
  reportId 를 주지 않는다. Bearer 필수(무토큰 → 401 `USER005`).
  사유 5개: `ABUSE`·`SPAM`·`FRAUD`·`SEXUAL`·`ETC`. 실측(2026-11-01, 로컬 `:8080`)으로 전부 확인했다.
- ★ **27 긴급 신고(`POST /api/v1/reports`)와 다른 것이다.** 그쪽은 「파티 + 내 좌표」를 신고하고
  사유 필드가 없고 112 통화로 이어진다. 이쪽은 **메시지 1건**과 그 글을 쓴 사람을 가리키고 후속
  통화가 없다. 한 DTO·한 화면으로 합치면 서버가 둘 다 400 을 낸다 —
  `AuthenticatedPathContractTest.메시지 신고와 긴급 신고는 서로 다른 본문 타입을 쓴다` 가 막는다.
  색도 나눴다: 빨강(`SafetyButton`·`ReportRed`)은 **긴급 신고 전용**이라 쓰지 않았다.
- ★ **같은 메시지는 한 번만 신고된다. 사유를 바꿔도 409 다.** 중복 판정이 「신고자 + 메시지」
  단위라 사유별로 쌓이지 않는다(실측). 그래서 409 `CHAT_ALREADY_REPORTED` 는 **재시도 가능한
  실패로 보여 주지 않는다** — 시트를 열어 두면 다섯 사유를 돌아가며 눌러도 전부 거절되는 곳에
  사용자가 갇힌다(`ChatException.isAlreadyReported` KDoc).
- **「기타」만 상세가 필수다. 공백만 적어도 거절된다**(서버가 `isBlank` 로 본다 → 400
  `CHAT_REPORT_DESCRIPTION_REQUIRED`). 그 밖의 사유는 **생략해도 201** 이다 — 엔티티에
  `@Column(nullable = false)` 가 붙어 있지만 마이그레이션이 nullable 이라 통과한다. 화면은 전송
  버튼으로 미리 막고, 저장소도 공백을 null 로 접는다(이중 방어).
- **종료된 방에서도 받는다.** 신고는 채팅방 참여 여부(`validateParticipant`)만 보고 파티 상태를
  보지 않는다 — CANCELED 파티의 방에서도 201(실측). 위치 공유와 **권한 기준이 다른 지점**이다.
- **403 이 두 종류다.** 신고 = `CHAT_NOT_PARTICIPANT`(없는 방도 404 가 아니라 이 403 이다),
  위치 공유 = `CHAT_NOT_PARTY_MEMBER`. 기존 `ChatException.isNotParticipant` 는 뒤쪽을 **못 잡는다**
  (code 가 non-null 이라 `httpStatus == 403` 분기도 안 탄다). `ChatReportErrorTest` 가 못 박는다.
- **404 도 둘이다.** `CHAT_MESSAGE_NOT_FOUND` 는 `isRoomNotFound` 로 안 잡혀 전용 플래그
  (`isMessageNotFound`)를 뒀다 — 묶으면 지워진 메시지를 신고했을 때 「채팅방이 사라졌어요」가 뜬다.
- **운영 대응은 적지 않는다.** 코드가 보장하는 것은 서버가 `chat_report` 에 한 줄 저장하고
  피신고자 인덱스를 거는 것까지다. 12 매너 서약의 「불쾌한 말과 행동을 하지 않을게요」 설명을
  **「채팅방에서 메시지를 길게 눌러 신고할 수 있어요」**로 되살렸지만(2026-10-13 에 비운 줄),
  2026-10-13 에 지운 「신고가 들어오면 24시간 안에 확인해요」는 돌아오지 않았다 — 시한도 제재도
  어느 코드가 보장하지 않는다. `ProductClaimsTest.매너 서약은 신고 뒤 운영 대응을 약속하지 않는다`
  가 시한·「접수되면」·「경고」·「정지」를 금칙어로 막는다.
- **그리지 않는 것**: 신고 내역 조회(조회 API 없음) · 신고 취소(엔드포인트 없음) ·
  차단(기능 없음) · 23 동승자 프로필의 「신고」(§4 — 사용자 단위 신고 API 가 여전히 없다).
