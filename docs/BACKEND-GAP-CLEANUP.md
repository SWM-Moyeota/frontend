# 백엔드 미지원 기능 정리 이력

프론트엔드에 화면·코드는 있었지만 백엔드(Backend 저장소 `develop`)에 대응 API 가 없어 **동작하지 않거나 가짜 값을 보여주던 기능**을 걷어낸 기록이다.
원칙: 실데이터로 바꿀 수 있으면 바꾸고, 없으면 요소·라우트·코드를 제거한다. "준비 중" 같은 자리표시 문구로 대체하지 않는다.

- 프론트 기준: `refactor/remove-unused-screens` (origin/develop `79ad602` 위)
- 백엔드 기준: Backend `develop` `1a75f82`
- 상세 근거(파일:라인)와 백엔드 엔드포인트 전체 목록: `_workspace/102_audit_frontend_backend_gap.md`

## 2. 추가·변경한 것

- 12 매너 서약 맨 아래에 위치 공유 동의 항목 추가: 「운행 중 내 위치를 동승자와 공유하는 데 동의해요 — 매칭된 운행 동안에만 위치를 쓰고, 운행이 끝나면 공유도 함께 끝나요」. **서버에 저장 필드가 없어 전송하지 않는다**(가입 버튼 활성 조건에만 사용).
- 하단 탭·마이페이지 제목 「마이」 → 「마이페이지」, 탐색 제목 「동승 — 내 주변」 → 「근처 동승 찾기」, 홈 인사말 → 「{이름}님, 반가워요」.
- 33 도착 완료가 운행 종료 직후 방 정보를 잃던 버그 수정(`finishedRide` 로 보존).

## 3. 남겨 둔 것 (의도적)

- 12 매너 서약의 동의 항목과 「이용약관 · 개인정보 처리방침」 문구 — 동의 기록 API 가 없어도 사용자 고지 목적으로 유지. 약관 링크는 열릴 페이지가 없어 무동작.
- 27 긴급 신고(`POST /reports`, `PATCH /reports/call-result`) — 실제 연동.
- 10 "닉네임은 나중에 바꿀 수 있어요" — 2026-10-10 에 36 프로필 수정 화면이 생겨 실제로 지킬 수 있는 말이 됐다(`PATCH /users/me`).

## 4. 백엔드가 생기면 되살릴 수 있는 것

| 기능 | 필요한 API |
|---|---|
| 내 탑승 횟수(35) | `GET /users/info` 응답에 `rideCount` |
| 지난 탑승 기록(34) | 완료 방 목록 (`GET /users/me/parties?status=FINISHED`) |
| 최근 검색/목적지(14·15) | `feature/search-history` 브랜치 머지 또는 최근 목적지 API |
| 동승자 실시간 위치(26) | 백엔드에 이미 있는 `/chat-rooms/{id}/location*` + STOMP 로 재연동 |
| 결제·정산(28~32) | 요금 확정·결제·결제수단·영수증 API |
| 평가·매너 점수·후기(23·33) | 평가 API |
| ~~프로필 수정(35)~~ | **완료** — 36 프로필 수정(닉네임)으로 구현(2026-10-10). 사진은 업로드 API 가 없어 여전히 불가 |
| 사용자 신고(23) | 사용자 신고 API (현재는 긴급 신고·메시지 신고만) |
| 알림 설정(35) | 서버 저장 API. 지금은 앱 토글 없이 **OS 앱 알림 설정**으로 넘긴다(앱만의 토글은 기기를 바꾸면 되살아나 지킬 수 없는 약속이 된다) |
| 고객센터·탈퇴(35) | 각 API. 문의는 메일(`SupportLinks.CONTACT_EMAIL`)로 대신하고, 탈퇴는 Play 요건이라 **탈퇴 API + 웹 탈퇴 안내 페이지**가 필요하다 |
