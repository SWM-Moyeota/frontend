# 입력 — 제품 판단 4건 반영 (2026-10-28)

사용자가 앞선 리뷰에서 「제품 판단 필요」로 남겨 둔 4건에 결정을 내렸다.

## 1. 16 도착지 확인 — 「1인」 칩 유지 (A안)
- **결정:** 선택지 1/2/3 을 그대로 둔다. 혼자 타기를 상품으로 인정.
- **해야 할 일:** 1 을 고르면 만든 즉시 1/1 로 꽉 찬 방이 되어 **혼자 출발**한다는 사실을
  고르는 자리에서 알려 준다. 지금은 아무 안내 없이 꽉 찬 방이 생긴다.
- 근거: 서버 `Capacity` 는 방장 포함 총 인원. `Party.open` 이 생성자를 멤버로 넣고
  `members.size == capacity` 면 꽉 찬 것으로 본다.
- 대상: `presentation/.../feature/home/DestinationConfirmModal.kt:425-433`

## 2. 채팅 입력 1000자 — 실시간 카운터 + 초과 시 전송 잠금 (B안)
- **결정:** 입력창 위에 실시간 카운터를 띄우고(초과 시 강조) **그다음에** 전송 버튼을 잠근다.
- **반드시 지킬 것:** 「왜 막혔는지」가 **누르지 않아도 보여야** 한다. 버튼만 잠그면
  예전 500자 컷 시절의 「조용히 막힘」으로 반쯤 되돌아간다(그 사정이 코드 주석에 남아 있다).
- 현재: 전송 버튼 `input.isNotBlank() && !sending` (ChatScreen.kt:193), 길이 안 봄.
  1001자에서 누르면 ChatRoute.kt:557 이 막고 메시지로 알린다.
- 대상: `ChatScreen.kt`(카운터·버튼), `ChatRoute.kt`(기존 전송 검사는 **방어로 유지**)

## 3. `adjustNothing` → `adjustResize` + 실기 검증
- **결정:** 키보드가 올라올 때 창이 줄어 입력창이 가려지지 않게 한다.
- `minSdk = 24` 인데 `WindowInsets.ime` 는 API 30+ 에서만 플랫폼이 보고한다.
  `adjustNothing` 이면 API 24~29 에서 `imePadding()` 이 무효 → 키보드가 입력창을 덮는다.
- imePadding 사용 화면 **10개**: 채팅, 목적지 검색, 본인인증, 프로필 설정, 직장 인증,
  프로필 수정, 이메일 코드, 회원 탈퇴, 로그인, 학교 이메일 (= 가입 흐름 거의 전부)
- **검증 필수:** 매니페스트 한 줄로 끝나는지 **측정으로 확인**한다. `adjustResize` 가
  edge-to-edge(`decorFitsSystemWindows=false`)와 겹칠 때 API 29 에서 실제로 ime inset 이
  생기는지는 추정하지 말고 재야 한다. 안 되면 백포트를 구현한다.
- 회귀 위험: API 30+ 기기 레이아웃도 같이 움직인다 → 양쪽(API 29 · API 37) 다 본다.

## 4. 17 탐색 — 이미 참여 중인 방을 목록에서 제외 (B안, 판단 번복)
- **결정:** 걸러낸다.
- 번복 사유: 처음엔 「걸러내면 내 방으로 돌아갈 길이 없어진다」로 A를 권했으나 **틀렸다** —
  `ExploreScreen.kt:358-361` 에 진행 중 방 배너가 **같은 화면 맨 위에** 이미 있고
  한 번 눌러 21/25/26 으로 바로 간다(20 을 거치는 것보다 짧다).
  지금 목록의 내 방 카드는 「합류돼 보이지만 안 되는 카드」이고 눌러도 막힌 화면에 닿는다.
- **`joinGate` 의 `ALREADY_JOINED` 분기는 지우지 않는다** — 목록이 낡은 경우·알림으로
  바로 들어오는 경우의 방어로 남긴다. 거르는 건 17 목록 표시뿐이다.
- 도달 경로(참고): 21 매칭 대기의 **뒤로가기는 나가기가 아니다**(`onExitKeepingParty`,
  MainNavGraph.kt:765) — 방을 유지한 채 홈으로 가므로 참여 중에도 17 에 닿는다.
