## 3. 결함·관찰

### D-1 · 정보 — 복귀 때 나가는 상세 1건은 **21 이 아니라 ActiveParty 홀더**의 것

- **현상**: 앱 복귀 직후 `GET /api/v1/matching/rooms/{id}` 가 1건 나간다(ON_START +171ms, 측정 15:26:57.332).
  124 §7 #3 의 기대는 「복귀 시 상세 0건」이라 겉보기엔 어긋난다.
- **출처**: `presentation/src/main/kotlin/com/moyeota/presentation/core/MainNavGraph.kt:179-180`
  `LifecycleResumeEffect(Unit) { activePartyViewModel.refresh() }`
  → `ActivePartyViewModel.reload()` → `RemoteActivePartyRepository.resolve()`
  → `data/src/main/kotlin/com/moyeota/data/repository/RemoteActivePartyRepository.kt:120-131 verify()`
  → `rideRepository.getPartyDetail(id)`
- **근거 3가지**: ① 21 진입 시에도 같은 짝(상세 1 + 홀더 상세 1 = 123 A6 의 「2건」)이 나온다 ②
  21↔24 화면 왕복(호스트 lifecycle 이 STARTED 유지)에서는 **이 1건이 전혀 안 나온다**(상세 0건) — 앱
  복귀 때만 나온다 ③ 화면 상태 보정은 이 응답이 아니라 SSE `connected` 스냅샷이 했다(홀더는
  `MatchWaitingViewModel.UiState` 를 건드리지 않는다).
- **판정**: **124 의 회귀가 아니고 21 의 범위도 아니다.** 비용은 **앱 복귀 1회당 상세 1건**(주기 아님).
- **담당**: 굳이 줄이려면 api-integrator/compose-builder 공동 — 홀더의 복귀 1회 조회를 21 의 스냅샷으로
  대체하는 건 `ActiveParty.kt:259` KDoc 이 이미 「짧은 TTL 캐시 또는 21 스냅샷 밀어넣기」로 적어 둔 숙제다.
  **지금 고칠 필요는 없다.**

### D-2 · 정보(문서↔구현 불일치) — `READ_NOW` 는 **복귀 직후 종결된 스트림**에는 타지 않는다

- **현상**: §2-6 타임라인대로, 복귀 재구독이 403 으로 거부돼 `streamEnded = true` 가 돼도 폴백의 첫 조회는
  **6초 뒤**다. `READ_NOW`(즉시) 가 아니라 `WAIT_THEN_READ` 로 돈 것이다.
- **원인**: `presentation/src/main/kotlin/com/moyeota/presentation/feature/matching/MatchWaitingRoute.kt:359-371`
  ```kotlin
  combine(visible, _partyClosed, ::Pair).collectLatest { (shown, closed) ->
      val step = fallbackPollStep(shown, closed, fallbackDone, streamEnded)   // streamEnded 를 '읽기만' 한다
  ```
  `streamEnded` 는 `@Volatile var`(같은 파일 `:137`)라 **combine 의 입력이 아니다.** 복귀 순간 패스가
  시작될 때는 아직 false 이므로 `WAIT_THEN_READ` 로 확정되고, 그 뒤 403 으로 true 가 돼도 **이미 시작된
  패스는 다시 판정되지 않는다.** 즉 124 §3 표의 「폴백 첫 조회(`streamEnded`) = 즉시」는 **진입 시점에
  이미 종결돼 있던 경우에만** 맞고, 복귀 직후 종결되는 경우에는 성립하지 않는다.
- **영향**: 24 채팅방에 가려진 동안 방이 닫히면 홈 전이가 **항상 6초**다(124 §5 가 「`READ_NOW` 경로를
  타면 그보다 빠르다」고 적었지만 그 빠른 경로는 실제로 열리지 않는다). 사용자 피해는 없다 —
  124 §5 가 선언한 상한 안이고 화면이 갇히지도 않는다.
- **재현**: 21 → 「채팅 열기」 → (curl 로 방 닫기) → 뒤로. `/events` 403 시각과 상세 조회 시각 차 = 6.0초.
- **수정 제안(compose-builder, 선택)**: `streamEnded` 를 `MutableStateFlow<Boolean>` 으로 바꿔
  `combine(visible, _partyClosed, streamEnded)` 의 세 번째 입력으로 넣으면 종결되는 순간 패스가 다시
  판정돼 `READ_NOW` 가 실제로 열린다(전이 6.2초 → 0.2초). **또는** 124 §3·§5 의 문장을 실제 동작
  (「가려진 동안 닫히면 복귀 후 **항상** 약 6초」)에 맞게 고치는 것으로 충분하다. 둘 중 하나면 된다.
