## 3. 새 화면 구조

```
                  이전                                        지금
┌──────────────────────────────────┐      ┌──────────────────────────────────┐
│ 마이페이지                        │      │ 마이페이지                        │
│ ┌ 프로필 카드 (민준/닉네임…)  › ┐│      │ ┌ 프로필 카드 (민준/닉네임…)  › ┐│
│ [설정]  알림 설정            ↗  │      │ [설정]  알림 설정            ↗  │
│ (지원 카드 — 주소 없어 숨김)      │      │ [안내]  개인정보 처리방침     ↗  │
│                                  │      │ ──────  이용약관             ↗  │
│ 로그아웃            v1.0         │ ←작음 │ ──────  문의하기             ↗  │
│                                  │      │ [계정]  로그아웃             ›  │
│ ─────── 하프라인 (40dp 띄움)      │      │ ──────  탈퇴하기(빨강)        ›  │
│ [계정]                           │      │         탈퇴하면 계정과 저장한…   │
│ ┌ 탈퇴하기(빨강)             › ┐│      │              v1.0  (가운데)       │
│   계정과 저장한 정보가 사라지고…   │      │ (디버그) 개발자 옵션              │
│ (디버그) 개발자 옵션              │      └──────────────────────────────────┘
└──────────────────────────────────┘
```

- 같은 그룹은 **한 카드 + 구분선**(구분선은 글자 시작선에 맞춰 20dp 들여쓰기 — 기존 카드 규칙 그대로).
- 기호 규칙 유지: **↗ = 앱 밖**(알림 설정·개인정보·약관·문의) / **› = 앱 안**(프로필·로그아웃·탈퇴).
- 아이콘은 만들지 않았다. 레퍼런스는 행마다 아이콘이 있지만 이 앱에 자산이 없어, 급조한 그림은
  구분이 아니라 장식이 된다(기존 방침 그대로 **텍스트 + 꺾쇠**).
- 행 높이 56dp·글자 15sp Medium — 「설정」·「안내」·「계정」 전부 같다. **로그아웃만 작던 문제가 사라졌다.**
- 카드 안에서 빨강은 「탈퇴하기」 하나뿐이다(그래야 경고로 읽힌다).

### 판단 3개 (지시를 그대로 따르지 않은 부분)

| 항목 | 결정 | 이유 |
|---|---|---|
| 탈퇴 설명 문구 | 「**탈퇴하면** 계정과 저장한 정보가 사라지고 되돌릴 수 없어요」로 **두 글자 추가** | 로그아웃이 같은 카드로 들어오면서 주어 없는 문장이 **바로 위 로그아웃에까지 걸리는 말**로 읽힌다. 로그아웃은 아무것도 지우지 않는다. 테스트로 「탈퇴하면」 시작을 고정했다 |
| 「안내」 행 순서 | 개인정보 처리방침 → 이용약관 → 문의하기 (기존 코드는 문의 → 약관 → 개인정보) | 지시한 순서이자, 가장 많이 찾는 문서가 위다(스토어 심사도 이 경로를 본다) |
| 레퍼런스의 「로그인 수단 안내」 | **넣지 않았다** | 이 화면이 아는 서버 값은 이름뿐이다. 로그인 수단을 추측해 적으면 「없는 기능은 행을 만들지 않는다」 원칙을 깬다(테스트로 금지어에 넣었다) |

### 오탭 위험 — 보호 수단이 바뀌었다 (기록)

이전 구조의 보호는 **거리**였다(40dp + 하프라인). 레퍼런스 구조는 로그아웃과 탈퇴를 한 카드에
나란히 두므로 그 거리를 쓸 수 없다. 대신:

1. **색** — 탈퇴만 `Danger500`, 카드 안 유일한 빨강.
2. **확인 단계** — 로그아웃은 확인 다이얼로그(그대로 유지), 탈퇴는 37 에서 비밀번호 + 또 한 번의 다이얼로그.
3. **순서** — 파괴적인 쪽이 아래(테스트로 고정).

즉 **둘 중 어느 쪽을 잘못 눌러도 한 번 더 확인을 거친다.** 거리로 떼어 놓으려면 로그아웃을
작게 둬야 했고, 그게 원래 지적의 원인이었다.

## 4. SupportLinks 처리

```kotlin
val TERMS_URL            = "https://legal.moyeota.p-e.kr/terms/"
val PRIVACY_URL          = "https://legal.moyeota.p-e.kr/privacy/"
val CONTACT_EMAIL        = "codingforest17@gmail.com"
val ACCOUNT_DELETION_URL = "https://legal.moyeota.p-e.kr/account-deletion/"   // 신규
```

- KDoc 의 「아직 정해지지 않았다」를 **현재 사실**로 고쳤다: 2026-10-14 배포, 로그인 없이 열림,
  쓰는 화면 3곳(35·37·04) 명시. `PRIVACY_URL` 의 「만 14세 미만 고지가 들어가야 한다」는 유지.
- **null 숨김 동작은 그대로 두었다.** 이유를 KDoc 에 적었다 — 페이지가 내려가거나 도메인이
  만료되면 그 한 줄만 고쳐 행을 숨기는 것이 죽은 링크보다 낫고, 그게 **유일한 긴급 복구 경로**다.
  그래서 **테스트도 "비어 있지 않음"을 못 박지 않았다**(그러면 긴급 복구가 테스트에 막힌다).
  모양만 검사한다: 채워져 있다면 `https://` 로 시작하고 공백이 없고, 메일에는 `@` 가 있다.
  "릴리스 전에 채워져 있는가"는 `docs/RELEASE.md` 체크리스트가 본다.
- `SupportLinkTargets` 를 새로 둔 이유: 화면이 전역 object 를 직접 읽으면 **「주소 없는 상태」를
  프리뷰·테스트로 만들 수 없다.** 실제로 QA 가 상수를 바꿔 빌드하고 되돌리다 사고가 날 뻔했다
  (113 §O4 — 그 파일이 untracked 라 `git checkout` 이 안 됐다). 이제 값으로 넣는다.

### 계정 삭제 안내 페이지 — 37 에만 넣었다

**넣었다.** 단, 35 「안내」 카드에는 행을 두지 않고 **37 경고 카드 바로 아래 한 줄**로 넣었다
(「지워지는 것과 남는 것 자세히 보기 ↗」).

| 후보 | 판단 |
|---|---|
| 35 「안내」 카드에 행 추가 | **버렸다.** 「탈퇴하기」와 뜻이 겹치는 입구가 두 개 생긴다 — 하나는 브라우저로 나가고(↗) 하나는 계정을 지우는 길인데(›), 목록에서 둘 다 "계정 삭제"로 읽혀 **파괴적인 오탭 면적만 넓어진다.** 이번 작업의 요지가 「계정」 카드의 위계를 분명히 하는 것인데, 그 위에 비슷한 이름의 행을 하나 더 얹는 셈이다 |
| 37 안에 한 줄 | **채택.** 「무엇이 지워지나?」가 실제로 더 알고 싶어지는 자리는 네 줄 경고를 읽은 **직후**다 |
| 양쪽 다 | 버렸다(위와 같은 이유) |
| 아예 안 넣음 | 버렸다. 네 줄은 요약이고 전문(보관 기간·남는 데이터·처리 절차)이 따로 있는데, 되돌릴 수 없는 동작 앞에서 더 읽을 길을 막을 이유가 없다 |

**중복 회피:** 링크 문구는 네 줄을 되풀이하지 않는다. 「자세히 보기」가 아니라
**「지워지는 것과 남는 것 자세히 보기」** 라고 적은 이유는, 37 의 네 줄이 *지워지는 것*만 말하고
**남는 것**(지난 합승 기록은 지워지지 않는다)은 웹페이지에만 있기 때문이다 — 링크가 새로 주는
정보를 문구가 그대로 가리킨다. `AccountDeletionWarnings` 네 줄은 **한 글자도 고치지 않았다.**

배치: 입력란 **위**다. 아래에 두면 키보드가 올라온 순간 밀려 사라진다(37 을 다이얼로그로
만들지 않은 것과 같은 이유). 주소가 null 이면 줄을 그리지 않는다.

### 덤 — 04 로그인의 죽은 탭 (범위 밖이지만 같은 공백이었다)

「가입하면 이용약관 · 개인정보 처리방침에 동의하게 돼요」 줄에는 `onClick = {}` 과
`// 미연결 — 약관 뷰 필요` 가 붙어 있었다(127 보고서가 지적한 그대로). 주소가 없어 미뤄 둔
자리이고, **동의를 안내하는 화면에서 그 문서에 닿지 못하면 안내가 반쪽**이라 이번에 이었다.

- 문서 이름 **두 조각만** 링크다(`AnnotatedString` + `LinkAnnotation.Url`, 파랑 + 밑줄).
  줄 전체 탭은 두 문서를 가려낼 수 없어 되살리지 않았다.
- **플랫폼 URI 핸들러에 맡기지 않는다** — 브라우저 없는 기기에서 예외를 던진다.
  `LinkAnnotation` 에 리스너를 달아 다른 외부 이동과 같은 길(`core/ExternalIntents` → 안내 토스트)로 보낸다.
- 주소가 null 이면 **문장은 그대로 두고 링크만 사라진다.** 동의하게 된다는 사실은 주소와
  무관하게 참이라, 문장을 지우면 고지가 사라진다(테스트로 고정).

## 6. 새 컴포넌트를 만들지 않았다 (designsystem 무수정)

- 카드·머리말·행은 **기존 35 의 카드 스타일을 그대로** 썼다(흰 배경 · 18dp 라운드 · 4dp 그림자 ·
  `SoftDivider` 구분선 · 56dp 행). 색은 전부 `MoyeotaColor` + 기존 와이어프레임 그레이 상수이고
  **새로 추가한 hex 는 0개**다(`grep "Color(0x"` 로 확인 — 잡히는 줄 전부 이전부터 있던 상수 선언이다).
- `ExternalLinkIcon` 만 `private` → `internal` 로 올려 37 이 같은 ↗ 를 쓰게 했다. 기호의 뜻이
  두 화면에서 어긋나면 규칙 자체가 무의미해진다. **세 번째 화면이 쓰게 되면 designsystem 으로 올릴 자리다**
  (참고: `ChevronRightIcon` 사본이 이미 3개 있다 — `JoinConfirmScreen`·`RideDetailScreen`·`MyPageScreen`.
  이번에 합치지 않았다: 사용자에게 보이는 변화가 없는데 세 화면을 건드리는 위험만 생긴다).
