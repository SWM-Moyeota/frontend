# 64 · 합승 화면 시트 애니메이션/단일 지도 · 배너-줌 겹침 · 반경 칩 잘림

작성 2026-09-12. 실기 피드백 7건 중 2~6 (1·7 은 PR #23 에서 처리됨 — 폰 미설치 상태로 본 것).

## 2. 홈 진행 배너 ↔ 지도 줌 컨트롤(+/−) 겹침 (작은 폰)
- 네이버 지도의 UI 컨트롤은 **contentPadding 을 뺀 영역** 안에 배치된다(실측: 시트 접힘/펼침에 따라 +/− 가 세로로 이동).
- 수정: 홈·합승 모두 배너(상태바 포함) 높이를 `onSizeChanged` 로 재서 지도 `contentPadding(top = 배너 높이)` 로 넘김 → 줌 컨트롤이 배너 아래로 내려간다.

## 3·4·5. 합승(17~19) 시트
- 원인: PEEK/HALF/FULL 이 **서로 다른 컴포저블**(전체 지도 / 320dp 지도 / 지도 없음)로 갈아끼워졌다 → 단계마다 지도 재생성(타일 재로드·카메라 복원 = "지도가 새로 갱신"), 전환 애니메이션 없음, 타이틀 행의 「🗺 지도」 버튼이 생겼다 사라지며 행 높이가 흔들림, 헤더 문구가 「주변 합승」/「주변 N명」으로 갈림.
- 재구성:
  - **지도 하나**(BoxWithConstraints 배경, 항상 컴포지션 유지) + 시트 **높이만** 앵커(PEEK 96dp / HALF = 컨테이너−300dp / FULL = 컨테이너) 사이를 `Animatable`(260ms) 로 오간다. 드래그(`draggable`)는 세 단계 모두, 놓으면 속도·위치로 정착(`settleTarget`).
  - 지도 `contentPadding(bottom)` 은 목표 앵커 기준(FULL 은 HALF 값으로 고정 — 패딩이 뷰를 넘지 않게).
  - 타이틀 행 고정 44dp, 「🗺 지도」 제거. 접기/펼치기는 **헤더의 단일 토글**(HALF 「지도 접기 ⌄」 ↔ FULL 「지도 펼치기 ⌃」).
  - 문구 통일: 접힘 「주변 합승 N개 모집 중」 / 헤더 「주변 합승 N개 · 가까운 순」. N = 지도 범위 조회 결과 `parties.size`(마커와 같은 목록). `waitingCount`(멤버 합) 파라미터 제거.
  - `dragToTransition`(24dp 임계 전환) 삭제.

## 6. 16 도착지 확인 반경 칩
- 원인: `ConditionRow` 가 라벨 + `Spacer(weight)` + 고정폭 칩 3개라 360dp 폰에서 칩이 카드 밖으로 밀려 「500m」 잘림, 선택 칩 파란 배경이 카드 클립 밖으로.
- 수정: 칩 Row 를 `weight(1f)` + `Arrangement.spacedBy(6.dp, Alignment.End)` 로 남는 폭 안에 우측 정렬, 칩 패딩 20 → 14dp, 텍스트 `maxLines=1/softWrap=false`.

## 검증
- 빌드·presentation 단위 테스트 통과
- 에뮬레이터(Pixel 6): 접힘 「이 근처엔 합승이 없어요」 → 핸들 드래그 ↑ → 반펼침(지도 300dp + 「주변 합승 0개 · 가까운 순」「지도 접기 ⌄」) → 탭 → 전체 목록(「지도 펼치기 ⌃」) → 탭 → 반펼침 → 드래그 ↓ → 접힘. 전환마다 지도 인스턴스 유지(재로드 없음), 260ms 애니메이션
- 배너-줌 겹침·반경 칩은 재현 조건(진행 중 파티 · 작은 폰)이라 실기 미확인 — 코드상 배치 규칙으로 해결
