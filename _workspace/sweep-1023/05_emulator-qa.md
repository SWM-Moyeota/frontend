## 1. 새 도메인 — 실측 확인

로그인을 누르고 logcat 에서 실제 요청을 떴다.

```
--> POST https://api.moyeota.co.kr/api/v1/auth/login
<-- 401 https://api.moyeota.co.kr/api/v1/auth/login
```

`api.moyeota.p-e.kr` 로 가는 요청은 없었다. `local.properties` 의 `MOYEOTA_BASE_URL`
오버라이드가 주석 처리돼 있어 `app/build.gradle.kts` 의 기본값이 그대로 쓰인다.

## 2. ALB 503 을 앱이 견디는가 — 운 좋게 실측했다

검증 도중 백엔드 prod 배포가 돌아서 **ALB 가 503 을 주는 창**에 걸렸다. 덕분에 평소
만들기 어려운 상황을 그대로 확인했다.

```
<-- 503 https://api.moyeota.co.kr/api/v1/auth/login
I/okhttp.OkHttpClient: <html>
I/okhttp.OkHttpClient: <head><title>503 Service Temporarily Unavailable</title></head>
```

**ALB 가 주는 503 은 JSON 이 아니라 HTML 이다.** 서버가 주는 `{"code":...}` 를 기대하는
파서에 HTML 이 들어가면 터지기 쉬운데, 앱은 터지지 않고

> 잠시 후 다시 시도해 주세요

를 보여줬다. 원문 HTML 이 화면에 새는 일도 없었다.

## 3. 장애와 인증 실패를 구분하는가

같은 자격증명으로 서버가 살아난 뒤 다시 눌렀다.

| 서버 응답 | 화면 문구 |
|---|---|
| `503` (ALB, HTML) | 잠시 후 다시 시도해 주세요 |
| `401` `{"code":"USER102"}` | 아이디 또는 비밀번호가 올바르지 않아요 |

두 상황이 **다른 문구로 갈린다.** 서버가 죽었는데 "비밀번호가 틀렸다"고 하면 사용자가
멀쩡한 비밀번호를 계속 고쳐 넣게 되므로, 이 구분은 중요하다.

## 4. 방장 전용 「합승 완료」 버튼 — 미검증, 그리고 왜 안 했는지

`canFinishParty` 는 방장에게만 완료 버튼을 준다. 이걸 실기로 보려면 **계정 2개로 같은
방에 들어가야** 한다.

지금 붙을 수 있는 서버는 prod 하나뿐이다(로컬 백엔드는 떠 있지 않다). 그런데 **prod 에는
비공개 테스트 테스터들이 실제로 들어와 있다.** QA 계정으로 방을 만들면 그 방이 테스터들의
근처 탐색 목록에 뜬다. 그래서 계정을 만들지 않고 멈췄다 — 사용자 확인이 필요하다.

선택지:
- 로컬 백엔드를 띄워 거기서 검증 (prod 무오염, 다만 로컬이 `members[].host` 를 주는
  최신 코드인지 확인 필요)
- prod 에 QA 계정 2개를 만들고 방은 **만들자마자 지운다**
- 테스터가 적은 시간대로 미룬다

## 5. 검증 중 드러난 운영 문제 — 배포 = 전면 다운

이건 앱 결함이 아니라 인프라 사실이지만, 비공개 테스트 중이라 영향이 크다.

```
moyeota-prod-tg  타겟 1대 (i-0d0a1147479d4ce1e, moyeota-backend-prod-a)
배포 시작 → 그 1대가 draining → healthy 타겟 0 → ALB 가 503
```

실측 다운타임 **약 7분**(12:23 시작, 12:30 경 200 회복). 두 도메인이 같은 ALB 를 쓰므로
`api.moyeota.co.kr` 과 `api.moyeota.p-e.kr` 이 **같이** 죽는다. 즉 새 빌드로 갈아타도
이 문제는 그대로다.

테스터는 이 7분 동안 앱이 "잠시 후 다시 시도해 주세요"만 보게 된다. 도플리가 "매일 실행되면
통과"라고 했으므로, 테스터 실행 시각과 배포 시각이 겹치면 그날 실행이 헛돌 수 있다.

팀원이 이미 관련 PR 을 올려뒀다 — 백엔드 `fix/graceful-shutdown`
("단일 서버 배포에서 종료할 때 남은 채팅 작업을 마무리하고 내려가게 함"). 다만 그건 **종료를
깔끔하게** 하는 것이고, **다운타임 자체를 없애지는 못한다**. 그러려면 타겟이 2대 이상이어야
한다(dev 는 이미 2대다).

## 재현 방법

```bash
ADB=~/Library/Android/sdk/platform-tools/adb
$ADB shell pm clear com.moyeota
$ADB shell am start -n com.moyeota/com.moyeota.app.MainActivity
$ADB logcat -c
# ... 로그인 시도 ...
$ADB logcat -d | grep -oE "(-->|<--) [A-Z0-9]+ https?://[^ ]+"
```

**좌표를 하드코딩하지 마라.** 에러 박스가 뜨면 로그인 버튼이 아래로 밀린다(1190 → 1345).
`uiautomator dump` 로 매번 `bounds` 를 읽어 누르는 쪽이 맞다 — 이번에도 밀린 좌표를
누르다 한 번 헛쳤다.
