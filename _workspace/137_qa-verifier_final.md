### A3. 360×640dp 에서 잘리는가 / 숨는가 → **잘린다. 단 스크롤하면 완전히 보인다**

(`wm size 720x1280` + `wm density 320`, `sw360dp`)

- 16 모달의 스크롤 영역(`ScrollView`, 라이브 측정) = **`[0,616][720,968]`** (352px = 176dp)
- **인원 칩 자체가 초기 화면에 없다** — 그 안에서 스크롤해야 `[*,867][*,915]` 로 도달한다
- 1명 선택 직후 안내 bounds = **`[72,945][515,968]`** → 뷰포트 바닥 `968` 에 **걸려서 23px 만 보인다**
  (같은 줄의 온전한 높이는 48px @320dpi / 63px @420dpi = 24dp)
- 스크롤을 조금 내리면 **`[72,813][515,861]` (48px 전체)** 로 **완전히 읽힌다**

→ **「숨어서 못 본다」가 아니라 「경계에 걸려 잘리고, 스크롤하면 닿는다」.** 심각도 낮음.
→ 네이티브(1080x2400)에는 **스크롤 노드 자체가 없다**(내용이 다 들어간다). 작은 폰에서만 생기는 현상이다.

## B. 17 탐색 — 내 방 거르기

구성: 스텁이 방 2개(**partyId 1 = 내 방**, partyId 2 = 남의 방). 진행 중 방 조회도 **id 1** 을 돌려주므로
`activeRide.id == 1` 로 짝이 맞는다(지시하신 id 짝 확인 완료 — 거르기가 돌 조건이 성립).
재현: 앱 시작 → 21 매칭 대기 복원 → **뒤로가기**(나가기 아님) → 홈 → 「동승」 탭.

### B1. 카드 목록에서 내 방만 빠지는가 → **그렇다**

```
주변 동승 1개 · 가까운 순
  출발지 : 낙성대역 4번 출구   목적지 : 사당역   2/3명  [합류]
```
- 남의 방(낙성대역→사당역) **남음** ✓
- 내 방(서울대입구역 2번 출구→강남역) **없음** ✓
- 헤더 카운트도 「1개」 — 서버는 2개를 줬다(`GET /api/v1/matching/rooms -> 200`)

### B2. 지도 마커에서도 빠지는가 → **그렇다 (핀도 1개)**

지도에 핀이 **정확히 1개**, 라벨 **「2/3명」** = 남의 방. 내 방(1/3명) 핀 **없음**.
→ 「카드만 빠지고 핀이 남는」 최악 케이스는 **아니다**. 카드와 마커가 일치한다.

> 관측 조건 메모: 스텁 방 좌표가 서울(37.48/126.95)인데 에뮬레이터 GPS 는 Mountain View 라
> 처음엔 **두 방 다 화면 밖**이어서 판정이 불가능했다. `adb emu geo fix` 는 앱 bbox 에 반영되지
> 않아, **스텁 좌표를 지도 뷰포트 안(37.425/-122.084, 37.4262/-122.0815)으로 옮겨** 관측했다.
> 거르기 로직은 좌표와 무관(id 비교)하므로 판정에는 영향 없다.

### B3. 진행 중 방 배너와 복귀 경로 → **둘 다 정상**

- 배너 유지: `● 같이 탈 사람 찾는 중  강남역   보기 ›` (지도 상단)
- 「보기 ›」 탭 → **21 매칭 대기로 복귀**: 「같이 탈 사람을 찾고 있어요」·「그만 찾기」·
  「서울대입구역 2번 출구」 확인 ✓
→ 카드를 지운 대가로 복귀 경로가 사라지지 않았다. 거르기 결정의 전제가 유지된다.

### B4. 내 방만 있을 때 문구 → **「지금은 내 방뿐이에요」 맞다**

스텁을 **내 방 1개만** 주도록 바꾼 뒤:
```
지금은 내 방뿐이에요
지도를 움직여 다른 방을 찾아보세요
```
- 「주변에 방이 없어요」 계열 **0건** ✓ — 거짓말하지 않는다
