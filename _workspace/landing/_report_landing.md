## 3. 명세와 다르게 간 곳 (전부 이유가 있다)

### 3-1. 히어로 스테이지 높이를 기기 폭에 묶었다 — **가장 큰 변경**

명세(§4-2)는 스테이지 높이를 `clamp(440px, 112vw, 580px)` 로 따로 적었다. 그러면 잘림 비율이
**폭마다 12~19% 로 흔들리고, 390px 에서 19% 가 잘려 홈 시트의 「목적지 검색」 칸까지 사라진다.**
명세 자신이 「홈 상단(지도·목적지 입력)이 가장 중요하고 하단 탭은 잘려도 된다」고 적은 의도와 어긋난다.

```css
.hero { --dev-w: clamp(13.5rem, 58vw, 17.5rem); --dev-top: var(--s-6); --hero-show: .875; }
.hero__stage { height: calc(var(--dev-w) * 20 / 9 * var(--hero-show) + var(--dev-top)); }
```

→ **모든 폭에서 잘림이 12.6~12.7% 로 같다**(실측). 하단 탭 바만 잘리고 검색 칸은 남는다.
잘림 자체는 명세의 장치 그대로 유지했다 — 어느 폭에서도 기기가 패널 안에 다 들어가지 않는다.

### 3-2. 가치 카드: 1100px 브레이크포인트를 하나 더 두었다

명세는 ≥900px 에서 카드를 `1fr 1.1fr` 2열로 가르라고 했다. 실측하면 **900px 화면에서 카드 칸이
412px, 안쪽 글 칸이 168px** 밖에 안 나온다 — 한 줄에 8자도 안 들어간다.
그래서 카드 안쪽 2열은 **1100px 부터** 켠다. 900~1099px 에서는 1열이다.
밴드 자체의 2열(제목 | 카드)은 명세대로 900px 에서 갈라진다.

제목 칸 비율도 `1fr 1.25fr` → **`minmax(0,22rem) minmax(0,1fr)`** 로 바꿨다.
짧은 제목이 500px 를 차지하고 카드가 눌리는 걸 막기 위해서다.

### 3-3. 띠의 칸 간격을 `gap` 이 아니라 `margin-inline-end` 로

명세(§4-4)의 `gap: clamp(12px,2vw,20px)` + `padding: 0 var(--gutter)` 를 그대로 쓰면
**`translateX(-50%)` 가 한 묶음과 어긋나 한 바퀴마다 튄다.** 8칸 사이에는 gap 이 7개뿐이고
좌우 패딩까지 폭에 들어가기 때문이다.

각 칸에 `margin-inline-end` 를 주면 총폭이 정확히 `16 × (칸 + 여백)` 이 되어 절반이 한 묶음과 같아진다.
**실측 이음매 오차 0.000px** (1280px·360px 양쪽).

같은 이유로 들쭉날쭉한 높이도 명세의 `:nth-child(2n)`/`(3n)` 대신 **주기 8**(`8n+2`, `8n+6`, `8n+7`, `8n+4`)로 바꿨다.
2n·3n 의 합성 주기는 6 이라 8칸짜리 두 묶음의 스카이라인이 달라진다. 실측 `[0,40,0,16,0,40,24,0]` 두 묶음 동일.

### 3-4. 「다운로드」 섹션 제목

명세의 `곧 Google Play 에서 받을 수 있어요` 는 **시점을 약속**한다(「곧」). 스토어 등록 일정을
확인할 수 없어 **`설치는 아직 / 준비 중이에요`** 로 바꿨다. 아래 문단이 사실을 설명하고,
칩은 명세대로 `<span>` 이다. 만 14세 이상 가입 사실을 fine print 에 더했다.

### 3-5. 가치 카드 2 의 제목

명세는 `확인된 사람과` 였다. **「확인된 사람」 배지는 서버 TODO 때문에 어떤 경우에도 뜨지 않는다**(D-2).
없는 배지를 제목으로 올리면 거짓이 된다 → **`누가 타는지 보고 타요`**.
본문은 실제로 확인되는 것만 적었다(휴대폰 인증 가입 · 닉네임과 탑승 횟수 · 실명/연락처 비공개).

### 3-6. 문서 섹션에 보이는 제목을 두었다

명세 §7-1 은 `h2.visually-hidden`(「법적 문서」)을 지시했다. 법적 사이트 홈은 페이지 제목이
「법적 고지」라 카드만 있어도 맥락이 서지만, **랜딩에서는 상단 앵커 「문서」가 제목 없는 블록에 착지한다.**
`p.eyebrow 문서` + `h2 약속은 문서에 / 적어 뒀어요` + 리드 한 줄을 넣었다.
띠(`#shots`)는 명세대로 `visually-hidden` 제목을 유지했다.

### 3-7. 파일 이름 · CSS 분량

- 명세 §8 의 `assets/landing.css` 대신 **`assets/style.css`** (요청서의 지시).
  법적 사이트와 다른 폴더라 충돌이 없다.
- 명세의 CSS 예산 22 KB 를 넘겼다 — **43.4 KB (gzip 13.3 KB)**. 복사해 온 법적 사이트 블록과
  유도 과정 주석이 대부분이다. 전송 기준으로는 예산 안이고, 주석을 지우는 쪽보다 남기는 쪽이 낫다고 판단했다.
- 섹션 라벨(`.eyebrow`)은 명세 §3-4 대로 `--link`(7.40 AAA)로 썼다. 법적 사이트는 `--mute` 다 —
  **의도적으로 갈라지는 유일한 자리**이고, 토큰 값은 건드리지 않았다.

- **`14-home` 만 목표를 못 맞췄다.** 화면 대부분이 네이버 지도 벡터 렌더(잔글씨·색면이 촘촘)라

- **D-crop 은 명세와 다르게 내보냈다.** 원본 996×402 의 네 모서리에는 **카드 둥근 모서리(반경 36px)
  바깥의 흰 자투리**가 남아 있다. 라이트 모드에서는 흰 카드에 묻히지만 **다크 모드에서는 흰 점으로 보인다.**
  → 사방 12px 안쪽으로 잘라 **972×378** 로 만든 뒤 ×2/3 축소해 **648×252**(정확히 나누어떨어진다).
  둥근 모서리는 우리 `.value-card__shot` 의 `border-radius` 가 대신 준다.
- 모든 `<img>` 에 `width`/`height` 가 박혀 있고, `.device` 가 `aspect-ratio: 9/20` + 명시 `width` 를
  가지므로 **이미지가 뜨기 전에 높이가 확정된다 — CLS 0.** 히어로 1장만 `fetchpriority="high"`.

### 4-1. 띠 이미지에서 `loading="lazy"` 를 뺐다 — 실측으로 잡은 결함

명세 §8 은 히어로를 뺀 8장 전부에 `loading="lazy"` 를 지시한다. 띠에 그대로 적용하면
**복제(두 번째) 묶음이 끝까지 안 뜬다.** 그 8칸은 **가로로만** 뷰포트 밖에 있어
세로 스크롤로는 영영 들어오지 않고, 마퀴가 `translateX` 로 밀어 넣어도 크롬의 네이티브
지연 로딩이 따라오지 못한다. 실측:

```
t= 0s  복제 묶음 로드 0/8     t=20s  0/8     t=35s  0/8
t=40s  1/8  ← 칸이 뷰포트 코앞(x=427, 뷰포트 390)에 와서야 겨우 하나
```

→ **루프 두 번째 바퀴에 빈 기기 틀이 줄지어 지나간다.** 띠 16칸에서 `loading="lazy"` 를 뺐다.
**URL 이 첫 묶음과 똑같아 요청 수는 그대로 9개**다(브라우저가 같은 URL 을 두 번 받지 않는다).
단계·가치 카드의 6장은 진짜로 한참 아래에 있으므로 `lazy` 를 유지했다.

확인: 로드 직후 **띠 16/16 · 히어로 1/1**, 맨 아래까지 스크롤하면 **23/23** 전부 complete.

## 5. 검증 수치

헤드리스 크롬(Chrome 141, `--headless=new`)을 **CDP 로 직접 몰아** 측정했다.
`--window-size` 는 macOS 에서 **500px 밑으로 안 내려간다** — 320·390px 측정이 통째로 거짓이 된다.

## 6. 남은 것 · 주의

1. **배포 주소가 없다.** `moyeota.p-e.kr` 은 2026-10-14 기준 DNS 가 없다(`curl` exit 6).
   `canonical` 과 `og:url` 이 그 주소로 적혀 있고 **HTML 에 경고 주석을 달아 뒀다.**
   주소가 정해지면 둘을 같이 고칠 것.
2. **`_design_spec.md` 와 `_shots.md` 는 세션 임시 폴더에만 있다.** 이 보고서가 요약하고 있지만,
   원본을 남기려면 이 폴더로 복사해야 한다(법적 사이트가 소스를 잃은 그 사고와 같은 조건이다).
3. **스크린샷은 개발 중 디버그 빌드**다. 푸터 고지가 그걸 말한다. 백엔드 결함 2건
   (D-1 즐겨찾기 500 · D-2 `badgeId` null)이 고쳐지면 **`15-destination` 과 `23-partner-profile` 을
   다시 찍어** 단계 01 의 ★ 문장과 가치 카드 2 의 「확인된 사람」을 되살릴 수 있다.
4. **1인 부담 4,233원**은 나누어떨어지지 않는 숫자다(`_shots.md` §4-2). 더 깔끔한 숫자를 원하면
   다른 목적지로 방을 새로 만들어 20 을 다시 찍어야 한다(같은 좌표는 Redis 캐시).
5. `animation-timeline: view()` 는 Chrome 에만 있다. Safari·Firefox 에서는 **스크롤 등장이 없을 뿐**
   레이아웃은 같다 — `@supports` 밖에 `opacity:0` 이 없으므로 내용이 사라지는 사고는 구조적으로 불가능하다.
