# 29. 가입 플로우에서 09 본인 인증 제거 — 10 프로필로 입력 통합 (compose-builder)

작업일: 2026-09-02 / 브랜치: `feature/naver-map` / 선행: `27_compose-builder_signup_merge.md`
요청: "회원가입 화면에서 휴대폰 인증 부분은 MVP 기준이라 지금은 없어도 되니까 해당 화면 빼줘"
범위: `presentation/` 만. `data/`·`domain/` 무수정.

---

## 1. 새 가입 플로우 (3단계)

```
04 시작 「이메일로 시작하기」 ┐
04a 로그인 「가입하기」        ┘→ 10 프로필 만들기(1/3, 서버 가입 7개 값 전부)
                              → 11 안심 설정(2/3) → 12 매너 서약(3/3, POST /users + 자동 로그인)
                              → 13 완료 → 14 홈
```

빠진 화면: 05 계정 유형 · 06 학교 이메일 · 07 인증 코드 · 08 재직 인증 **· 09 본인 인증(이번)**.

09 는 "통신사 선택 + 휴대폰 인증" 컨셉이었지만 백엔드에 SMS 인증 API 가 없어 이미 인증 없이
값만 받는 폼이었다(27 보고서 §5 에서 CTA 를 「인증 문자 받기」 → 「다음」으로 고친 것도 같은 이유).
MVP 에서 인증을 빼면 화면이 남길 것은 입력 4개뿐이므로 화면을 지우고 입력만 옮겼다.

## 2. 09 가 받던 값은 하나도 잃지 않았다

가입 API(`POST /api/v1/users`)는 `loginId·password·name·birthDate·phoneNumber·gender·email`
7개를 요구한다. 09 가 앞 4개(name·phone·birth·gender), 10 이 뒤 3개를 받고 있었다.
이제 **10 한 화면이 7개를 모두 받는다.**

| 09 에 있던 것 | 처리 |
|---|---|
| 이름(실명) · 생년월일 · 성별 · 휴대폰 번호 | 10 「기본 정보」 절로 이관 (검증 규칙 동일) |
| 생년월일·휴대폰 포맷 입력(D-7 `DigitGroupVisualTransformation`) | 그대로 이관 — value 는 원시 숫자, 하이픈은 표시만 |
| 통신사 선택 (SKT/KT/LG U+/알뜰폰) | **가입 경로에서 완전 제거** (파일 안에만 남음) |
| 「이용약관 · 개인정보 수집에 동의해요」 체크 | 12 매너 서약의 동의 묶음으로 통합 (§5) |
| 「성별은 동성 매칭에만 써요」 안내 카드 | 성별 칩 아래 한 줄 캡션으로 축약 |

## 3. 10 프로필 만들기 — 필드 7개를 세 절로

필드가 7개(+표시 이름)라 스크롤이 필요해졌다. 리디자인 대신 **머리말로만 끊었다.**

| 절 | 필드 |
|---|---|
| 프로필 | 아바타 톤 · 표시 이름 (상대에게 보이는 이름, 카운터 n/8) |
| 기본 정보 | 이름(실명) · 생년월일 · 성별 · 휴대폰 번호 |
| 로그인 정보 | 아이디 · 비밀번호 · 이메일 |

- 헤드라인은 「어떻게 불러드릴까요?」 → **「가입 정보를 알려주세요」**. 이제 표시 이름만 묻는
  화면이 아니어서 앞 문구는 화면 내용과 맞지 않는다. 부제는 09 의 「실명과 성별은 매칭 안전을
  위해서만 사용해요」를 가져왔다(서버에 저장되는 값이라 "저장 안 해요"라고 쓸 수 없다).
- 실명과 표시 이름은 **따로 받는다.** 실명을 표시 이름에 자동 복사하는 것도 고려했지만,
  타이핑 도중 「이름」과 「표시 이름」 두 곳에서 동시에 에러가 뜨는 구간이 생겨 뺐다.
- `initialDisplayName` 파라미터 제거(09 에서 넘어오던 값이 없어졌다). 표시 이름 helper 문구는
  이름 필드만 유효하면 뜨도록 고쳤다 — 예전에는 폼 전체가 유효해야 떠서, 필드가 7개가 된
  지금은 마지막 한 글자를 칠 때까지 안 보인다.
- 콜백은 `onNext(displayName, SignupDraft)` 로 바꿨다. 인자 8개짜리 람다를 만드는 대신
  **서버로 갈 7개 값 = `SignupDraft`** 를 그대로 넘긴다. 표시 이름은 가입 API 에 자리가 없어 따로 둔다.

## 4. 진행 표시 재계산 (n/4 → n/3)

| 화면 | 이전 | 이후 |
|---|---|---|
| 09 본인 인증 | 1 / 4 | — (경로에서 빠짐, 파일 값은 손대지 않음) |
| 10 프로필 | 2 / 4 | **1 / 3** (`1f/3f`) |
| 11 안심 설정 | 3 / 4 | **2 / 3** (`2f/3f`) |
| 12 매너 서약 | 4 / 4 | **3 / 3** (진행 바는 그대로 `1f`) |

## 5. 약관 동의는 12 한 곳으로

09 의 「이용약관 · 개인정보 수집에 동의해요」 체크박스를 12 매너 서약의 동의 항목(맨 위)으로 옮겼다.
설명은 「실명·생년월일·연락처는 본인 확인과 매칭 안전에만 써요」.

- 12 의 「아래 내용에 모두 동의해요」 일괄 체크가 이 항목까지 함께 켜고 끈다 → 전체 동의 없이는
  CTA 가 비활성인 기존 규칙이 그대로 적용된다.
- 중복은 없다 — 12 의 기존 4개는 **행동 서약**(시간 약속·정산·매너·노쇼)이고 약관·개인정보 동의는
  거기 없었다. 동의를 두 화면이 나눠 받던 구조가 한 화면으로 모인 것이다.
- `checks` 배열을 `mutableStateListOf(false, false, false, false)` → `Array(pledgeItems.size)` 로
  바꿨다. 항목을 늘리면서 체크 배열 길이를 안 고치면 인덱스 예외가 난다.

## 6. 09 화면 파일 보존 방식 (05~08 과 동일)

`IdentityVerifyScreen.kt` 는 **지우지 않았다.** 실제 본인 인증(SMS·PASS)을 붙일 때 통신사 선택
UI 와 폼 배치를 재사용한다.

- `MainNavGraph` 의 `composable(Routes.IDENTITY_VERIFY)` 와 import 제거 → 그래프에서 도달 불가
- `Routes.IDENTITY_VERIFY` 상수는 **B' 「미연결」 절로 이동** + 사유 주석. 상수를 지우면 화면 파일이
  어디에 붙던 것인지 단서가 사라진다
- 파일 상단에 「⚠️ 현재 어떤 그래프에도 등록되어 있지 않다」 배너 + 되살릴 때 필요한 4가지
  (그래프 재등록 · 진행 표시 재계산 · 10 과 중복 입력 정리 · 약관 동의 중복 확인)
- 09 의 진행 표시 「1 / 4」 는 그대로 뒀다 — 도달 불가이고, 되살릴 때는 단계 수가 다시 정해진다
  (06~08 의 「1 / 5」 를 남겨둔 것과 같은 이유)

## 7. 검증 규칙은 옮기기만 — 새 파일 `SignupFieldSupport.kt`

09 안에 private 로 있던 것들을 패키지 공용(internal)으로 끌어올렸다. **규칙은 한 글자도 바꾸지
않았다.** 09 파일이 남아 있어 그대로 두면 같은 규칙을 두 파일이 복제하게 된다.

| 옮긴 것 | 내용 |
|---|---|
| `PersonNameRegex` | 한글 또는 영문 2~20자 (서버 `NAME_MAX_LENGTH`) |
| `parseBirthDate` · `MIN_BIRTH_YEAR` | YYYYMMDD → `LocalDate`, 없는 날짜(20250230)·미래 날짜 거부 |
| `SimpleEmailRegex` | 10 에 private 로 있던 것 (같은 자리에 모았다) |
| `SignupChoiceChip` | 09 의 `IdentityCarrierOption` 을 이름만 바꿔 공용화 (성별 2택에 사용) |

경과 기록: 첫 시도는 `presentation` 이 아니라 **`data` 모듈에서 실패**했다. 병렬 인증 작업이

그 시점에도 단독으로 `:presentation:compileDebugKotlin BUILD SUCCESSFUL` 이었다.

## 11. 남긴 관찰

### 🟡 실명과 표시 이름을 한 화면에서 두 번 묻는다

같은 화면에 「이름(실명)」과 「표시 이름」이 함께 놓이면서 사용자가 이름을 두 번 입력한다.
합치기 전에는 09 → 10 으로 화면이 달라 덜 드러나던 문제다(그때는 실명이 표시 이름에 프리필됐다).
자동 복사를 넣지 않은 이유는 §3 에 적었다 — 실명이 2자일 때 표시 이름(3자 이상)이 즉시 에러가 나고,
타이핑 중 두 필드에서 에러가 동시에 뜬다. 표시 이름을 **선택 입력으로 바꾸고 비우면 실명을 쓰는**
쪽이 정답으로 보이는데, 이건 카피·정책 결정이라 지시 없이 하지 않았다.

### 🟡 표시 이름 값은 여전히 서버로 가지 않는다

`POST /api/v1/users` 에 자리가 없어 `MainNavGraph` 가 받자마자 버린다(합치기 전과 동일).
가입 후 홈·마이의 이름이 데모 값 「김OO」로 나오는 것도 같은 이유다(`signup3_15`, `signup3_16`).
서버에 표시 이름 필드가 생기면 이 화면은 이미 값을 들고 있으니 배선만 이으면 된다.

### 🟢 11 안심 설정 카드 상단의 빈 영역은 이번 변경과 무관

`signup3_10` 에서 카드 위쪽 70dp 가 비어 보이는데, 와이어프레임 여백을 그대로 옮긴
기존 코드(`Spacer(Modifier.height(70.dp))` + 「와이어프레임 카드 상단 여백 영역」 주석)다.
이번 작업에서는 이 화면의 진행 표시만 건드렸다.
